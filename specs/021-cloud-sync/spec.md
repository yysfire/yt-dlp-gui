# Feature Specification: 云与同步 (Cloud & Sync)

**Feature Branch**: `021-cloud-sync`
**Created**: 2026-05-31
**Status**: Draft
**Input**: From PRD v1.0 for yt-dlp subscription manager desktop app (P3 Ecosystem Phase)

## User Scenarios & Testing *(mandatory)*

### 1. 多设备间同步订阅和设置
**User Story**: 作为一名在两台电脑上使用本应用的用户，我想要自动同步订阅列表和设置，以便在任何设备上都能获得一致的体验。
**Why this priority**: 多设备同步是解决用户"换设备后需要重新配置"痛点的核心功能。
**Independent Test**: 在设备 A 添加一个订阅，设备 B 在 30 秒内自动同步显示新订阅。

**Given** 用户在设备 A 和设备 B 上登录同一账号
**When** 用户在设备 A 上添加一个新订阅
**Then** 设备 B 在 30 秒内自动同步并显示新订阅
**And** 下载设置、分类规则等配置也同步到设备 B

### 2. 云端备份和恢复
**User Story**: 作为一名担心数据丢失的用户，我想要将订阅和下载记录自动备份到云端，以便在重装系统后快速恢复。
**Why this priority**: 数据安全是用户的核心关切，云端备份是防止数据丢失的最后防线。
**Independent Test**: 手动触发云端备份，然后在另一设备上从云端恢复。

**Given** 用户拥有 50 个订阅和 500 条下载记录
**When** 用户点击"立即备份到云端"
**Then** 所有订阅、设置、下载记录上传到云端存储
**And** 显示备份完成时间、文件大小和备份 ID
**And** 在另一台设备上点击"从云端恢复"后，所有数据恢复一致

### 3. 远程管理下载任务
**User Story**: 作为一名在外出时需要管理下载的用户，我想要通过手机查看下载状态并远程添加下载任务，以便利用家中的带宽资源。
**Why this priority**: 远程管理让用户可以随时随地利用桌面端的下载能力。
**Independent Test**: 用手机浏览器打开远程控制面板，添加一个 YouTube 视频下载任务。

**Given** 用户在家中电脑上运行应用并开启远程管理
**When** 用户在手机上通过浏览器访问远程管理界面
**Then** 可以看到所有订阅状态和下载进度
**And** 可以粘贴视频链接并提交下载任务
**And** 下载完成后收到推送通知

### 4. 移动端伴侣应用集成
**User Story**: 作为一名移动优先的用户，我想要在手机上通过伴侣应用浏览订阅更新，以便在通勤时决定哪些值得下载到桌面。
**Why this priority**: 移动端伴侣应用是生态闭环的关键一环，覆盖用户的全场景使用。
**Independent Test**: 在手机上安装伴侣应用，扫描桌面端二维码配对，浏览最新视频列表。

**Given** 手机安装伴侣应用，桌面端运行并显示配对二维码
**When** 用户在伴侣应用中扫描二维码完成配对
**Then** 伴侣应用显示桌面端的订阅列表和最新视频
**And** 用户可以在手机上标记"稍后下载"的视频
**And** 桌面端在下次检查时自动下载标记的视频

## Requirements *(mandatory)*

### 功能需求

#### 多设备同步
- **FR-001**: 系统必须支持用户账号注册和登录（邮箱 + 密码）
- **FR-002**: 系统必须支持实时同步订阅列表变更（添加、删除、修改）
- **FR-003**: 系统必须支持同步应用设置（下载路径、画质偏好、通知设置）
- **FR-004**: 系统必须支持冲突解决策略：最后修改时间优先、手动选择
- **FR-005**: 系统必须在离线时缓存变更，联网后自动同步
- **FR-006**: 系统必须区分"设备本地"和"云端同步"的设置（如代理设置仅本地）

#### 云备份
- **FR-007**: 系统必须支持手动触发全量云备份
- **FR-008**: 系统必须支持自动定时备份（每日/每周/每月）
- **FR-009**: 系统必须支持增量备份（仅上传变更数据）
- **FR-010**: 系统必须保存最近 10 个备份版本，支持选择版本恢复
- **FR-011**: 系统必须对备份数据进行端到端加密（E2EE）
- **FR-012**: 恢复备份前必须显示备份摘要（时间、设备、订阅数、记录数）

#### 远程管理
- **FR-013**: 系统必须提供安全的远程管理 Web 界面（HTTPS）
- **FR-014**: 远程管理必须支持添加/删除订阅和触发下载
- **FR-015**: 远程管理必须显示实时下载进度和系统状态
- **FR-016**: 远程访问必须通过强密码 + 可选 2FA 认证
- **FR-017**: 系统必须记录远程管理操作日志
- **FR-018**: 远程管理连接必须支持 WebSocket 实现实时推送

#### 移动端伴侣应用
- **FR-019**: 桌面端必须提供配对机制（二维码 + 配对码）
- **FR-020**: 移动端必须显示订阅列表和最新视频预览
- **FR-021**: 移动端必须支持标记"稍后下载"和"已观看"
- **FR-022**: 移动端必须支持推送通知（新视频发布、下载完成）
- **FR-023**: 配对关系必须支持管理（查看已配对设备、解除绑定）
- **FR-024**: 移动端与桌面端通信必须端到端加密

#### 浏览器扩展
- **FR-025**: 浏览器扩展必须支持一键添加当前页面视频/频道为订阅
- **FR-026**: 浏览器扩展必须显示当前订阅状态（频道名、最新视频数）
- **FR-027**: 浏览器扩展必须通过本地 API 与桌面应用通信
- **FR-028**: 浏览器扩展必须支持主流浏览器（Chrome、Firefox、Edge）

### 关键实体

- **UserAccount**: 用户账号（id、邮箱、密码哈希、注册时间、订阅计划）
- **SyncRecord**: 同步记录（实体类型、实体 ID、变更类型、时间戳、设备 ID）
- **CloudBackup**: 云备份（id、时间戳、设备、订阅数、记录数、大小、加密状态）
- **RemoteSession**: 远程会话（session_id、设备、IP、开始时间、最后活动时间）
- **PairedDevice**: 已配对设备（设备名、设备类型、配对时间、最后同步时间）
- **BrowserExtensionToken**: 浏览器扩展认证（token、浏览器类型、创建时间）

## Success Criteria *(mandatory)*

### 可衡量的成果
- **SC-001**: 多设备同步延迟 P95 不超过 30 秒
- **SC-002**: 云端备份 100 个订阅 + 2000 条记录的上传时间不超过 30 秒
- **SC-003**: 云备份恢复完整性达到 100%（零数据丢失）
- **SC-004**: 远程管理 Web 界面在 3G 网络下加载时间不超过 5 秒
- **SC-005**: 移动端配对流程从扫码到完成不超过 15 秒
- **SC-006**: 浏览器扩展一键添加订阅的响应时间不超过 1 秒
- **SC-007**: 端到端加密对备份/恢复性能影响不超过 10%
- **SC-008**: 系统在离线状态下缓存至少 100 条待同步变更

## Assumptions

- 云服务需要后端服务器支持，P3 阶段完成客户端 SDK 和协议设计
- 用户数据存储在自建服务器或用户自选的 S3 兼容存储
- 移动端伴侣应用为独立项目，本规范仅覆盖桌面端所需的 API 和配对机制
- 远程管理使用基于 WebSocket 的中继服务器，不要求用户有公网 IP
- 浏览器扩展基于 WebExtensions 标准开发，Chrome/Firefox/Edge 共享 90% 代码
- E2EE 使用用户密码派生的密钥，用户需妥善保管密码
