# Quality Checklist: 订阅管理增强

**Feature**: 006-subscription-management-enhanced
**Phase**: P1 Enhancement
**Last Updated**: 2026-05-31

## 需求完整性检查

- [ ] 所有用户故事都有 Given/When/Then 验收场景
- [ ] 每个用户故事都定义了独立测试方法
- [ ] 所有边缘情况都已记录（导入编码、重复检测、网络中断等）
- [ ] 功能需求（FR）覆盖所有用户故事中的能力描述
- [ ] 非功能需求（性能、可靠性）在 Success Criteria 中可度量
- [ ] 关键实体（SubscriptionTag, HealthCheckResult, ImportResult）已定义数据结构
- [ ] 数据持久化策略明确（标签持久化到 subscriptions.json）

## 技术可行性检查

- [ ] OPML 解析复用现有 `services/opml.rs` 的能力范围已评估
- [ ] 批量导入异步并行的并发上限已定义（不超过 5 个并发解析）
- [ ] 健康检查的 HTTP 请求不会触发平台反爬机制
- [ ] 标签模型与前端的双向绑定可行（React 状态 + Rust 命令）
- [ ] 搜索功能在前端本地过滤，无需后端调用
- [ ] 详情面板的视频列表数据获取方式与 yt-dlp 集成确认

## 用户体验检查

- [ ] 批量导入提供进度条和可取消操作
- [ ] 导入结果提供明确的成功/失败统计
- [ ] 健康检查结果可直观区分正常/警告/失效
- [ ] 筛选条件组合的 UI 交互清晰（非隐藏的过滤逻辑）
- [ ] 标签颜色选择器不超过 12 种预定义颜色
- [ ] 详情面板加载状态有骨架屏或加载指示器
- [ ] 所有列表操作支持键盘导航（Tab、方向键、Enter）

## 兼容性与边界检查

- [ ] OPML 导入兼容不同 RSS 阅读器导出的格式（Feedly、Inoreader、Google Podcasts）
- [ ] TXT 导入兼容 CRLF 和 LF 换行符
- [ ] 批量导入中部分失败不影响已成功项
- [ ] 标签名称限制 50 字符且有前端输入验证
- [ ] 订阅数 0 时筛选/排序界面不崩溃
- [ ] 订阅数 500+ 时筛选不卡顿

## 安全性检查

- [ ] 导入的 URL 经过验证，防止路径遍历或命令注入
- [ ] OPML XML 解析防范 XXE（XML External Entity）攻击
- [ ] 健康检查不泄露用户网络环境信息

## 测试覆盖检查

- [ ] OPML 导入单元测试覆盖正常格式、空文件、损坏文件、非 UTF-8 编码
- [ ] TXT 导入单元测试覆盖空行、注释行、无效 URL
- [ ] 健康检查单元测试覆盖各种 HTTP 状态码（200/301/404/429/500）
- [ ] 标签 CRUD 单元测试覆盖创建、重命名、删除、批量分配
- [ ] 筛选逻辑单元测试覆盖多条件组合
- [ ] 前端筛选组件测试覆盖实时搜索、高亮

## 依赖与集成检查

- [ ] 与 `useSubscriptions()` Hook 的接口兼容性已验证
- [ ] 与 `src/lib/tauri.ts` 新增 invoke 命令的命名一致
- [ ] 与 AppState 的标签状态管理集成无冲突
- [ ] 与 settings.json 的筛选偏好存储字段协调
