# Quality Checklist: 文件命名与组织

**Feature**: 008-file-naming-organization
**Phase**: P1 Enhancement
**Last Updated**: 2026-05-31

## 需求完整性检查

- [ ] 所有用户故事都有 Given/When/Then 验收场景
- [ ] 每个用户故事都定义了独立测试方法
- [ ] 所有边缘情况都已记录（空模板、路径超长、Windows 保留名、全角字符等）
- [ ] 功能需求（FR）覆盖所有用户故事中的能力描述
- [ ] 非功能需求（渲染时间、准确率、跨平台兼容）在 Success Criteria 中可度量
- [ ] 关键实体（FilenameTemplate、ConflictStrategy、OrganizeMode）已定义
- [ ] 模板与自动组织的优先级关系已明确（模板优先）

## 技术可行性检查

- [ ] yt-dlp 输出模板占位符完整列表已确认
- [ ] 文件名清理逻辑是否会与 yt-dlp 的 `--restrict-filenames` 冲突
- [ ] 路径长度检查在跨平台场景下正确（Windows 需特殊处理）
- [ ] 自动重命名的序号增长策略在并发下载时线程安全
- [ ] 模板预览功能不实际调用 yt-dlp，使用本地字符串替换

## 用户体验检查

- [ ] 模板输入框有占位符提示和语法帮助
- [ ] 模板预览实时更新，不需要点击确认
- [ ] 冲突策略选择器使用单选框，三种策略并列展示
- [ ] "按频道组织"选项对拥有 50+ 订阅的用户仍方便使用
- [ ] 特殊字符清理结果在文件名预览中可见
- [ ] 所有设置项有合理的默认值

## 兼容性与边界检查

- [ ] Windows 文件名保留名称完整列表已覆盖
- [ ] macOS 处理 Unicode NFD（Normalization Form D）文件名
- [ ] 文件名长度 > 255 字符的截断策略不会截断扩展名
- [ ] 空模板（仅 `%(ext)s`）不会导致崩溃
- [ ] 频道名完全由 Emoji 组成时的文件夹名回退方案
- [ ] 组合使用组织选项不会产生循环路径

## 安全性检查

- [ ] 文件名模板不会导致路径遍历（`../` 必须过滤）
- [ ] 用户输入的文件名不被用于命令注入
- [ ] 模板中的路径分隔符 `/` 规范化为操作系统对应分隔符

## 测试覆盖检查

- [ ] 模板解析单元测试覆盖所有已知占位符、未知占位符、空值占位符
- [ ] 时长后缀检测单元测试覆盖 `(HH:MM:SS)`、`【时长 HH:MM:SS】`、嵌套括号、标题含正常时间
- [ ] 特殊字符清理单元测试覆盖所有禁止字符、首尾空格、尾部句点、纯特殊字符标题
- [ ] 自动组织路径构建测试覆盖所有组合模式
- [ ] 文件冲突策略单元测试覆盖自动重命名序号、路径超长回退、跨模式场景

## 依赖与集成检查

- [ ] 与 `services/ytdlp.rs` 的命令参数构建逻辑兼容
- [ ] 与 `services/storage.rs` 的 settings.json 存储结构兼容
- [ ] 与 `commands/download.rs` 的下载流程中文件名构建位置协调
- [ ] 与前端 SettingsDialog 的设置项 UI 组件集成
- [ ] 文件名处理为纯 Rust 端逻辑，不依赖前端
