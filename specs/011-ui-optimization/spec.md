# Feature Specification: 界面优化

**Feature Branch**: `001-mvp-core-features`

**Created**: 2026-05-31

**Status**: Draft

**Input**: 来自 PRD v1.0，yt-dlp 桌面端订阅管理器 (P1 Enhancement Phase)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 响应式布局 (Priority: P1)

用户在调整窗口大小时，界面应自适应调整布局，在不同窗口尺寸下保持良好的可用性和可读性。

**Why this priority**: 用户在不同分辨率的显示器上使用应用，响应式布局确保所有场景下的基本可用性。

**Independent Test**: 拖动窗口边缘调整大小，验证界面元素在 800x600 到 4K 分辨率下均可正常使用。

**Acceptance Scenarios**:

1. **Given** 用户使用默认窗口尺寸，**When** 用户将窗口缩小到最小尺寸 (800x600)，**Then** 订阅列表、详情面板、工具栏仍然可见且可操作，无元素重叠。
2. **Given** 用户使用小窗口尺寸，**When** 用户最大化窗口，**Then** 所有界面元素按比例扩展，内容区域充分利用屏幕空间。
3. **Given** 用户使用平板/笔记本小屏幕，**When** 侧边栏折叠状态切换，**Then** 主内容区域自动填充可用空间。

---

### User Story 2 - 拖拽支持 (Priority: P2)

用户可以通过拖拽操作来管理订阅排序、将文件拖拽到应用中导入，提升操作效率。

**Why this priority**: 拖拽操作大幅提升高频操作效率，但基础功能（点击操作）已能满足基本需求。

**Independent Test**: 在订阅列表中拖拽一个订阅项到新位置，验证排序是否更新并持久化。

**Acceptance Scenarios**:

1. **Given** 用户有多个订阅，**When** 用户拖拽某个订阅项移动到新位置，**Then** 订阅顺序更新并保存到本地。
2. **Given** 用户有一个 OPML 文件在桌面上，**When** 用户将文件拖拽到订阅列表区域，**Then** 触发批量导入流程。
3. **Given** 用户拖拽一个订阅项到无效区域，**When** 松开鼠标，**Then** 订阅项回到原位，无任何变更。

---

### User Story 3 - 右键菜单 (Priority: P2)

用户在订阅、下载记录等条目上右键点击时，弹出上下文菜单提供快捷操作。

**Why this priority**: 右键菜单是桌面应用的标准交互模式，能显著减少鼠标移动距离和操作步骤。

**Independent Test**: 在订阅列表中的某个订阅上右键点击，验证弹出的菜单包含删除、暂停、检查更新等选项，且点击后功能正常执行。

**Acceptance Scenarios**:

1. **Given** 用户在订阅列表页面，**When** 在某个订阅项上右键点击，**Then** 弹出上下文菜单，包含暂停/启用、删除、检查更新、修改画质等选项。
2. **Given** 用户在下载记录列表页面，**When** 在某条记录上右键点击，**Then** 弹出上下文菜单，包含打开文件位置、复制链接、删除记录等选项。
3. **Given** 用户打开右键菜单后，**When** 点击菜单外的区域，**Then** 菜单自动关闭。

---

### User Story 4 - 状态实时更新 (Priority: P1)

下载过程中的状态变化（如"下载中"→"已完成"）应实时反映在界面上，无需用户手动刷新。

**Why this priority**: 下载是核心功能，用户需要实时了解下载进度和状态，手动刷新会严重降低使用体验。

**Independent Test**: 触发一个订阅检查/下载操作，观察下载记录列表中的状态是否自动从"下载中"变为"已完成"。

**Acceptance Scenarios**:

1. **Given** 下载正在进行中，**When** 一个新下载任务开始，**Then** 下载列表中实时出现该条记录，状态显示为"下载中"。
2. **Given** 一个下载任务正在进行，**When** 下载完成，**Then** 该记录状态自动更新为"已完成"，无需刷新页面。
3. **Given** 一个下载任务正在下载中，**When** 下载失败，**Then** 记录状态自动更新为"失败"，并显示错误原因。
4. **Given** 后台定时检查完成，**When** 有新视频被发现并开始下载，**Then** 状态栏更新最后检查时间，下载列表自动刷新。

---

### User Story 5 - 下载完成通知 (Priority: P3)

当视频下载完成时，向用户发送桌面通知，让用户即使不在应用窗口前也能知晓下载进度。

**Why this priority**: 桌面通知提升用户体验，但不影响核心功能使用流程。

**Independent Test**: 触发下载任务，切换窗口到其他应用，验证系统通知是否正确弹出。

**Acceptance Scenarios**:

1. **Given** 用户开启了下载通知并且下载正在进行，**When** 视频下载完成，**Then** 系统发送桌面通知，包含视频标题和频道名称。
2. **Given** 用户未开启下载通知，**When** 视频下载完成，**Then** 不发送桌面通知。
3. **Given** 通知已弹出，**When** 用户点击通知，**Then** 将应用窗口切换到前台。

---

### Edge Cases

- 频繁调整窗口大小（如拖拽边缘快速改变尺寸）时界面不应闪烁或崩溃。
- 拖拽操作与系统文本选择交互冲突时的处理。
- 右键菜单在屏幕边缘时自动调整弹出位置，避免超出可视区域。
- 大量实时更新事件同时到达时（如批量检查 20+ 个订阅），界面不应卡顿。
- 用户在下载通知弹出时正在全屏应用中，通知应正确处理。
- 通知权限被系统级禁止时应用不应崩溃。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持窗口尺寸在 800x600 至全屏之间自适应调整，所有界面元素保持可用。
- **FR-002**: 系统 MUST 支持侧边栏折叠/展开，折叠时主内容区域自动扩展。
- **FR-003**: 系统 MUST 支持订阅列表中的拖拽排序，排序结果持久化保存。
- **FR-004**: 系统 MUST 支持从文件管理器拖拽 OPML/TXT 文件到窗口作为导入操作。
- **FR-005**: 系统 MUST 为订阅列表、下载记录列表、设置面板提供右键上下文菜单。
- **FR-006**: 右键菜单 MUST 根据选中条目的类型和状态动态调整可用选项。
- **FR-007**: 系统 MUST 在收到后端 `records-changed` 事件时自动刷新下载记录列表。
- **FR-008**: 系统 MUST 在收到后端 `download-complete` 事件时发送桌面通知（若用户已开启通知）。
- **FR-009**: 桌面通知 MUST 包含下载视频的标题和来源频道名称。
- **FR-010**: 系统 MUST 在用户点击通知时将应用窗口置于前台。
- **FR-011**: 右键菜单和拖拽操作 MUST 有视觉反馈（高亮、阴影、动画），引导用户操作。

### Key Entities

- **UI 布局状态**: 侧边栏折叠/展开状态、窗口尺寸、上次订阅排序
- **通知设置**: 是否启用、通知内容模板
- **右键菜单配置**: 按条目类型分类的操作项列表

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 窗口尺寸变化后 500ms 内完成界面重新布局，无可见延迟或闪烁。
- **SC-002**: 拖拽订阅排序操作在松开鼠标后 200ms 内完成 UI 更新。
- **SC-003**: 右键菜单在点击后 100ms 内弹出。
- **SC-004**: 下载状态变化在收到后端事件后 300ms 内反映到界面上。
- **SC-005**: 拖拽和右键菜单在连续操作 20 次后无内存泄漏或性能下降。
- **SC-006**: 90% 的用户在首次使用时能独立完成拖拽排序和右键操作。

## Assumptions

- 应用已实现基本的订阅列表和下载记录列表 UI（来自 MVP 阶段）。
- 后端已支持 `records-changed` 和 `download-complete` 事件推送。
- 桌面通知依赖系统通知 API（Tauri notification plugin）。
- 拖拽排序存储依赖现有的订阅存储服务（subscriptions.json）。
- 响应式布局不做移动端/触屏优化，仅覆盖桌面端窗口尺寸范围。
- 右键菜单选项对应已实现的命令功能，不新增未实现的操作入口。
