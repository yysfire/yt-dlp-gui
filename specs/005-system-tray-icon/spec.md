# Feature Specification: 系统托盘图标

**Feature Branch**: `005-system-tray-icon`

**Created**: 2026-06-09

**Status**: Draft

**Input**: 用户描述: "规格 005 只保留 系统托盘图标的需求"

## Clarifications

### Session 2026-06-09

- Q: 桌面通知与托盘功能的关系 → A: 通知是已有独立功能，托盘规格只关注图标状态和 tooltip，不涉及通知
- Q: 托盘图标状态变化的视觉实现方式 → A: 使用单图标 + 编程叠加徽标（overlay/badge），在图标上覆盖下载箭头/检查标记
- Q: 启动时最小化到托盘的窗口闪烁行为 → A: 允许短暂闪烁但目标是逐步消除，接受当前技术限制下的最小化闪烁
- Q: 左键单击托盘图标的行为 → A: 左键单击同样触发显示/隐藏主窗口，与双击行为一致
- Q: 托盘操作的日志记录级别 → A: 记录关键事件（图标创建/销毁、状态切换、菜单点击）在 INFO 级别，异常在 WARN/ERROR

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 窗口最小化到系统托盘 (Priority: P1)

用户在使用 yt-dlp-gui 进行订阅检查和下载时，希望将窗口最小化到系统托盘，让应用在后台继续工作而不占用任务栏空间。这是桌面下载工具的标准行为。

**Why this priority**: 托盘行为是桌面应用的核心体验。若最小化后任务栏仍占用空间，用户无法获得后台运行的好处。

**Independent Test**: 打开应用后点击最小化按钮，验证窗口隐藏且系统托盘中出现应用图标，后台任务（如下载）继续进行。

**Acceptance Scenarios**:

1. **Given** 应用主窗口处于显示状态，**When** 用户点击窗口标题栏的最小化按钮，**Then** 主窗口隐藏，系统托盘区域出现应用图标，调度器和下载任务继续在后台运行。
2. **Given** 应用已最小化到系统托盘，**When** 用户左键单击（或双击）托盘图标，**Then** 主窗口恢复显示并置于前台，保持最小化前的界面状态。
3. **Given** 应用已最小化到系统托盘，**When** 用户右键托盘图标并选择"显示主窗口"，**Then** 主窗口恢复显示并置于前台。
4. **Given** 应用已最小化到系统托盘，**When** 当前有下载任务正在进行，**Then** 下载任务不受最小化影响，正常继续直至完成。

---

### User Story 2 - 托盘右键菜单提供快捷操作 (Priority: P1)

用户希望在不打开主窗口的情况下，通过托盘右键菜单快速执行常用操作，如检查全部订阅更新、暂停/恢复定时调度等。

**Why this priority**: 托盘菜单是托盘功能的核心价值——让用户在不切换窗口的情况下完成关键操作，与最小化到托盘同等重要。

**Independent Test**: 在托盘图标上右键，验证菜单弹出并包含预期选项，点击各选项验证对应功能正常执行。

**Acceptance Scenarios**:

1. **Given** 应用正在运行（无论窗口是否显示），**When** 用户右键点击系统托盘图标，**Then** 弹出上下文菜单，包含以下选项：
   - "显示主窗口"（或"隐藏主窗口"，根据窗口当前状态动态切换）
   - 分隔线
   - "检查全部订阅更新"
   - "暂停定时检查" 或 "恢复定时检查"（根据调度器当前状态动态切换）
   - 分隔线
   - "退出"
2. **Given** 托盘菜单已弹出，**When** 用户选择"检查全部订阅更新"，**Then** 后台启动全部订阅的检查流程，无需打开主窗口。
3. **Given** 调度器当前处于运行状态，**When** 用户选择"暂停定时检查"，**Then** 定时调度器停止，菜单选项变为"恢复定时检查"。
4. **Given** 调度器当前处于暂停状态，**When** 用户选择"恢复定时检查"，**Then** 定时调度器恢复运行，菜单选项变为"暂停定时检查"。
5. **Given** 托盘菜单已弹出，**When** 用户选择"退出"，**Then** 应用完全退出（如有进行中的下载任务，先确认是否终止），托盘图标消失。

---

### User Story 3 - 关闭窗口时最小化到托盘 (Priority: P2)

用户点击窗口关闭按钮（X）时，不希望退出应用，而是希望应用最小化到系统托盘继续后台运行。这是下载类桌面应用的常见行为模式。

**Why this priority**: 关闭到托盘是提升用户体验的重要行为，避免用户误操作导致下载中断。但比最小化到托盘低一级，因为部分用户期望关闭按钮直接退出。

**Independent Test**: 在应用设置中启用"关闭到托盘"选项，点击窗口关闭按钮，验证窗口隐藏且托盘图标存在，应用进程继续运行。

**Acceptance Scenarios**:

1. **Given** 用户已在设置中启用"关闭到托盘"，**When** 用户点击窗口关闭按钮（X），**Then** 主窗口隐藏而非退出，系统托盘图标保持显示，后台任务继续运行。
2. **Given** 用户已在设置中启用"关闭到托盘"且主窗口已通过关闭按钮隐藏，**When** 用户通过托盘菜单选择"显示主窗口"，**Then** 主窗口恢复显示。
3. **Given** 用户未启用"关闭到托盘"（默认行为），**When** 用户点击窗口关闭按钮，**Then** 主窗口关闭，托盘图标消失，应用退出。
4. **Given** 用户点击关闭按钮时窗口已隐藏到托盘，**When** 用户通过托盘菜单选择"退出"，**Then** 应用完全退出。

---

### User Story 4 - 托盘图标状态指示 (Priority: P3)

用户希望在托盘图标上直观看到应用当前的运行状态，包括是否有下载活动、有新视频更新、空闲等状态，无需打开主窗口即可了解应用是否正在工作。

**Why this priority**: 状态指示是增值体验，让用户在不操作的情况下也能感知应用状态。但基础功能（显示/隐藏、菜单）已能满足核心需求。

**Independent Test**: 触发下载任务后最小化应用，观察托盘图标上是否出现叠加徽标（overlay）及提示文本变化。

**Acceptance Scenarios**:

1. **Given** 没有下载任务或检查任务在进行，**When** 用户查看托盘图标，**Then** 托盘图标显示默认空闲状态，鼠标悬停提示显示"yt-dlp 订阅管理器 - 空闲"。
2. **Given** 有下载任务正在进行，**When** 用户查看托盘图标，**Then** 托盘图标上叠加下载徽标（如下载箭头 overlay），鼠标悬停提示显示"正在下载 N 个视频"。
3. **Given** 调度器正在执行订阅检查，**When** 用户查看托盘图标，**Then** 托盘图标上叠加检查中徽标（如放大镜或刷新 overlay），鼠标悬停提示显示"正在检查订阅更新..."。
4. **Given** 下载任务全部完成，**When** 最后一项下载完成，**Then** 托盘图标恢复到空闲状态。

---

### Edge Cases

- 系统托盘在某些 Linux 桌面环境（如 i3、sway 等平铺窗口管理器）中不被原生支持时，托盘图标无法显示。此时应用应降级为普通窗口行为（关闭即退出），并在日志中记录不支持的系统信息。
- 托盘图标文件（icon.png）缺失或损坏时，应用应使用默认图标或显示文字提示，确保应用仍能正常运行。
- 快速连续双击托盘图标时，窗口状态不应出现闪烁或状态不一致。
- 应用通过系统关机或强制终止信号结束时，应保存当前状态（如调度器运行状态），下次启动时恢复。
- 在 macOS 上，Dock 图标和托盘图标（菜单栏图标）的交互行为差异——macOS 通常将小图标放在菜单栏而非 Dock 旁的托盘区。
- 用户通过托盘菜单退出时，如有未完成的下载任务，应提示确认，防止意外丢失下载进度。
- 应用启动时，如果用户设置了"启动时最小化到托盘"，应直接进入托盘状态。允许因平台限制导致的短暂窗口闪烁，但实现应尽可能通过窗口配置（如 `visible: false`）减少闪烁。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 应用启动时必须在系统托盘区域创建并显示应用图标。
- **FR-002**: 托盘图标必须响应鼠标左键单击事件，切换主窗口的显示/隐藏状态。
- **FR-003**: 托盘图标必须响应鼠标右键单击事件，弹出上下文菜单。
- **FR-004**: 托盘右键菜单必须包含以下基础选项：
  - "显示主窗口" / "隐藏主窗口"（根据窗口当前状态动态切换文本）
  - "检查全部订阅更新"
  - "暂停定时检查" / "恢复定时检查"（根据调度器状态动态切换文本）
  - "退出"
- **FR-005**: 必须为"暂停/恢复定时检查"菜单项提供独立的菜单事件处理，直接调用调度器控制逻辑。
- **FR-006**: 选择"退出"菜单项时，如有进行中的下载任务，必须先弹出确认对话框；如无进行中任务则直接退出；退出时清理托盘图标资源。
- **FR-007**: 托盘图标必须在鼠标悬停时显示提示文本（tooltip），展示应用名称及当前状态。
- **FR-008**: 托盘图标的提示文本必须根据应用状态动态更新：空闲时显示"yt-dlp 订阅管理器 - 空闲"，有下载任务时显示"正在下载 N 个视频"，检查更新时显示"正在检查订阅更新..."。
- **FR-009**: 托盘图标必须通过叠加层（overlay）方式体现运行状态：默认无叠加层（空闲），下载中叠加下载箭头徽标，检查中叠加刷新/放大镜徽标。
- **FR-010**: 系统必须允许用户配置"最小化到托盘"行为：当用户点击窗口最小化按钮时，窗口隐藏至系统托盘。
- **FR-011**: 系统必须允许用户配置"关闭到托盘"行为：当用户点击窗口关闭按钮时，窗口隐藏至系统托盘而非退出应用。
- **FR-012**: 系统必须允许用户配置"启动时最小化到托盘"行为：应用启动后直接进入托盘状态，不显示主窗口。
- **FR-013**: 当桌面环境不支持系统托盘时（如部分 Linux 平铺窗口管理器），应用必须降级为普通窗口模式，所有托盘行为失效，"关闭到托盘"等同于普通退出。
- **FR-014**: 应用退出时必须正确清理系统托盘图标资源，确保无残留图标。
- **FR-015**: 所有托盘相关行为配置（最小化到托盘、关闭到托盘、启动时最小化）必须持久化保存，应用重启后配置不丢失。
- **FR-016**: 系统必须记录托盘运行的关键事件日志：图标创建/销毁（INFO）、状态切换（INFO）、菜单项点击操作（INFO）、平台托盘不支持（WARN）、图标加载失败（ERROR）。

### Key Entities

- **托盘状态**: 描述托盘图标当前显示的视觉状态，包括：
  - 状态类型（空闲、下载中、检查中）
  - 关联的活跃任务数量（用于提示文本）
  - 是否在桌面环境不支持的情况下降级
  
- **托盘行为配置**: 用户对托盘行为的偏好设置，包括：
  - 最小化到托盘（布尔值）
  - 关闭到托盘（布尔值）
  - 启动时最小化（布尔值）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 托盘图标在应用启动后 2 秒内出现在系统托盘区域。
- **SC-002**: 右键点击托盘图标后，菜单在 300 毫秒内弹出。
- **SC-003**: 左键单击（或双击）托盘图标后，主窗口在 500 毫秒内恢复显示。
- **SC-004**: 托盘图标的状态更新（含提示文本变化）在状态变化后 1 秒内完成。
- **SC-005**: 在支持系统托盘的主流桌面环境（Windows 10+、macOS 11+、GNOME 3+、KDE Plasma 5+）中，托盘功能 100% 可用。
- **SC-006**: 在不支持系统托盘的桌面环境中，应用正常降级运行，无崩溃或错误提示。
- **SC-007**: 用户可在 3 次点击内完成"显示主窗口""检查全部更新""退出"等常用托盘操作。
- **SC-008**: 通过托盘菜单退出的确认对话框在不必要的情况下不弹出（无进行中下载时直接退出），减少用户操作步骤。

## Assumptions

- 系统托盘图标使用项目已有的应用图标（`src-tauri/icons/icon.png`），无需额外设计新图标。不同状态可通过图标叠加层（overlay）方式体现。
- Tauri v2 的核心托盘 API（`tauri::tray::TrayIconBuilder`）已可用，框架权限 `core:tray:default` 已在生成配置中就绪。
- 桌面通知为已有独立功能，托盘功能仅负责图标状态和 tooltip 更新，不管理通知的触发或显示。
- 托盘行为配置项将添加到现有的 `AppSettings` 结构体中，存储在 `settings.json`。
- 默认配置值：最小化到托盘=启用，关闭到托盘=启用（符合下载工具惯例），启动时最小化=禁用。
- 在 macOS 上，托盘图标将置于菜单栏（menu bar）而非 Dock 旁，符合 macOS 平台惯例。
- 应用只支持单实例运行，托盘行为不涉及多实例协调。
- 平台兼容范围：Windows 10+、macOS 11+、主流 Linux 桌面（GNOME、KDE、XFCE）。平铺窗口管理器（i3、sway）不保证托盘功能。
