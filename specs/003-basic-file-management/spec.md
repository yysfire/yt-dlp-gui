# Feature Specification: 基本文件管理

**Feature Branch**: `001-mvp-core-features`

**Created**: 2026-05-31

**Status**: Draft

**Input**: 来自 PRD v1.0，yt-dlp 桌面端订阅管理器

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看已下载视频列表 (Priority: P1)

用户可以浏览所有已下载的视频文件列表，查看文件名、下载时间、所属订阅频道、文件大小等信息。

**Why this priority**: 查看已下载内容是用户管理本地视频库的基础需求，使用频率高。

**Independent Test**: 下载几个视频后，打开文件管理页面，验证所有已下载视频是否正确显示。

**Acceptance Scenarios**:

1. **Given** 用户已下载多个视频，**When** 用户打开已下载视频列表，**Then** 以列表形式显示所有已下载视频，包含标题、所属频道、下载时间、文件大小。
2. **Given** 用户尚未下载任何视频，**When** 用户打开已下载视频列表，**Then** 显示空状态提示"暂无已下载的视频"。
3. **Given** 已下载视频列表中有大量条目，**When** 用户滚动浏览，**Then** 列表流畅加载，所有条目均可正常显示。

---

### User Story 2 - 打开文件所在位置 (Priority: P2)

用户可以从已下载视频列表中直接打开视频文件所在的文件夹，方便用户在系统文件管理器中管理文件。

**Why this priority**: 用户经常需要在下载后定位文件进行播放、移动或分享，此功能提升操作便捷性。

**Independent Test**: 在已下载视频列表中点击某个视频的"打开文件夹"按钮，验证系统文件管理器是否在正确路径打开。

**Acceptance Scenarios**:

1. **Given** 某个视频已下载且文件存在，**When** 用户点击"打开文件所在位置"，**Then** 系统文件管理器打开到该视频所在文件夹，并定位到该文件。
2. **Given** 某个视频的下载记录显示已完成，**When** 实际文件已被用户手动删除，**Then** 点击"打开文件所在位置"时打开到目录级别（而非文件），并提示用户文件可能已不存在。
3. **Given** 用户在 Windows 系统上，**When** 点击"打开文件所在位置"，**Then** 使用 Windows 资源管理器打开。
4. **Given** 用户在 macOS 系统上，**When** 点击"打开文件所在位置"，**Then** 使用 Finder 打开。

---

### User Story 3 - 搜索已下载视频 (Priority: P2)

用户可以通过搜索框输入关键词，快速在已下载视频中按标题筛选匹配的结果。

**Why this priority**: 当已下载视频数量增多时，搜索是最高效的查找方式。

**Independent Test**: 下载多个不同标题的视频，在搜索框中输入部分标题关键词，验证筛选结果是否准确。

**Acceptance Scenarios**:

1. **Given** 已下载视频列表中有多个视频，**When** 用户在搜索框输入视频标题中的关键词，**Then** 列表实时筛选，仅显示标题包含该关键词的视频。
2. **Given** 用户输入的关键词没有匹配任何视频，**When** 搜索完成，**Then** 显示"未找到匹配的视频"提示。
3. **Given** 用户清空搜索框，**When** 搜索框内容被清除，**Then** 列表恢复显示全部已下载视频。
4. **Given** 视频标题包含英文大小写混合，**When** 用户使用小写关键词搜索，**Then** 搜索不区分大小写，能正确匹配。

---

### User Story 4 - 文件系统同步检测 (Priority: P3)

系统定期检测已下载视频文件是否存在，标记用户手动删除或移动的视频，保持界面显示与实际文件状态一致。

**Why this priority**: 用户可能通过外部文件管理器删除了视频文件，应用需要反映真实状态，避免给用户错误的"已下载"信息。

**Independent Test**: 在文件管理器中手动删除某个已下载视频文件，然后在应用中触发同步（或等待自动检测），验证该视频被标记为"文件已缺失"。

**Acceptance Scenarios**:

1. **Given** 某个已下载视频的文件已被用户通过外部方式删除，**When** 应用执行文件系统同步，**Then** 该视频在列表中被标记为"文件已缺失"，提供视觉提示（如灰色显示或图标变化）。
2. **Given** 用户删除了多个已下载视频的文件，**When** 文件系统同步完成，**Then** 所有已缺失的视频均被正确标记。
3. **Given** 文件系统同步检测到文件缺失，**When** 用户选择保留该下载记录，**Then** 记录中标记为"文件已缺失"但不删除记录，用户可以查看历史下载信息。

---

### Edge Cases

- 下载路径被更改后，旧路径下的已下载文件如何处理？
- 下载路径包含特殊字符或超长路径时，打开文件夹功能是否正常工作？
- 用户同时打开多个文件夹时是否有性能问题？
- 搜索功能在标题包含特殊字符（emoji、多种语言混合）时是否能正常工作？
- 文件系统同步检测大量文件（1000+）时的性能如何？
- 外部存储（移动硬盘、网络驱动器）断连后，如何标记文件状态？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须以列表形式展示所有已下载视频的记录，包含标题、所属频道、下载时间、文件大小。
- **FR-002**: 系统必须支持按标题关键词搜索已下载视频。
- **FR-003**: 系统必须支持搜索不区分大小写。
- **FR-004**: 系统必须支持从列表中直接打开已下载视频文件所在的文件夹。
- **FR-005**: 系统必须检测已下载视频文件是否存在，标记已被外部删除的文件。
- **FR-006**: 系统必须在下载记录中持久化文件路径信息。
- **FR-007**: 系统必须在文件缺失时保留下载记录（而非直接删除记录）。
- **FR-008**: 系统必须支持跨平台打开文件所在位置（Windows/macOS/Linux）。

### Key Entities

- **DownloadRecord**: 下载记录实体（与下载功能共享），在此功能中关注文件路径、文件大小、文件是否存在标记、下载时间等字段。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已下载视频列表在包含 500 条记录时，首次加载时间不超过 2 秒。
- **SC-002**: 搜索筛选的响应时间不超过 500 毫秒（在 500 条记录中）。
- **SC-003**: "打开文件所在位置"操作在 2 秒内完成文件管理器的启动。
- **SC-004**: 文件系统同步检测 500 个文件的状态，耗时不超过 10 秒。
- **SC-005**: 文件存在性检测准确率达到 100%。

## Assumptions

- 下载的文件命名由 yt-dlp 的输出模板控制，文件路径唯一标识一个下载记录。
- 文件系统同步在应用启动时执行一次，以及用户手动触发时执行。
- 缺失文件以文件路径是否存在为依据，不校验文件内容完整性。
- 用户的操作系统支持通过默认文件管理器打开指定路径。
