# 需求质量检查清单: 智能下载管理 (012)

## 需求完整性

- [x] 所有用户故事具有明确的 Given/When/Then 结构
- [x] 功能需求覆盖所有用户故事中描述的场景
- [x] 关键实体定义完整，包含必要字段
- [x] 成功标准可量化、可验证
- [x] 假设条件已明确记录

## 技术可行性

- [x] 并发下载控制基于 tokio 异步运行时，Tauri 原生支持
- [x] 下载时间段限制使用系统本地时间，无外部依赖
- [x] 网络空闲检测通过 `/proc/net/dev`（Linux）和系统 API（Windows/macOS）实现，已验证跨平台可用
- [x] 断点续传复用 yt-dlp 内置 `--continue` 标志，无需自行实现文件分片
- [x] 磁盘空间监控使用 `std::fs` 和 `statvfs`，已在 Rust 标准库中

## 架构一致性

- [x] 下载队列管理遵循 Commands → Services 分层架构
- [x] 新模型（DownloadQueueEntry、NetworkMonitorState 等）遵循 Rust snake_case / TypeScript PascalCase 命名约定
- [x] 网络监控和磁盘检查作为独立服务实现，保持无状态
- [x] Tauri 事件用于推送队列状态更新（遵循现有 events 模式）
- [x] 下载记录状态扩展兼容现有 DownloadRecord 模型

## 边界条件

- [x] 并发设置为 0 时的行为已考虑（无限并发，需限制或阻止）
- [x] 跨天时间窗口正确处理（22:00 - 06:00）
- [x] 网络接口不存在或统计信息不可读时的降级策略
- [x] 部分下载文件被用户手动删除时的续传失败处理
- [x] 磁盘空间阈值设为 0 时的行为（不做检查，等同于关闭监控）

## 安全性

- [x] 无命令注入风险（下载参数通过 Rust 构建，不拼接用户输入）
- [x] 磁盘空间检查不暴露整个文件系统结构给前端
- [x] 网络统计信息仅显示聚合数据，不暴露具体连接详情
- [x] 下载队列优先级调整需权限校验（仅允许当前用户操作）

## 依赖与集成

- [x] yt-dlp `--continue` 标志在所有支持的 yt-dlp 版本中可用
- [x] `statvfs`/磁盘空间 API 在 Linux/macOS/Windows 平台均有对应实现
- [x] 网络监控在不同平台上使用条件编译实现适配
- [x] 与现有 scheduler.rs 和 download.rs 的集成点已明确
