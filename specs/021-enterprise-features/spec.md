# Feature Specification: 企业级功能 (Enterprise Features)

**Feature Branch**: `021-enterprise-features`
**Created**: 2026-05-31
**Status**: Draft
**Input**: From PRD v1.0 for yt-dlp subscription manager desktop app (P3 Ecosystem Phase)

## User Scenarios & Testing *(mandatory)*

### 1. 团队管理员集中管理订阅
**User Story**: 作为一名 IT 管理员，我想要为团队成员统一配置订阅源并管理下载策略，以便团队共享视频资源。
**Why this priority**: 多用户支持是企业场景的基础，决定了企业级功能的可行性。
**Independent Test**: 管理员创建 3 个团队账号，为团队订阅 5 个频道，成员登录后自动同步。

**Given** 管理员登录企业管理控制台
**When** 管理员创建团队"内容运营组"并添加 3 名成员
**And** 管理员为团队添加 5 个共享订阅源
**Then** 3 名成员登录后可看到团队的 5 个共享订阅
**And** 每个成员还可以添加个人私有订阅

### 2. 基于角色的权限控制
**User Story**: 作为一名部门主管，我想为团队成员分配不同权限（管理员/编辑者/查看者），以便控制谁能添加订阅和触发下载。
**Why this priority**: 权限管理是防止误操作和数据泄露的关键保障。
**Independent Test**: "查看者"角色尝试添加订阅被拒绝，"编辑者"角色可以正常添加。

**Given** 管理员为成员 A 分配"查看者"角色
**When** 成员 A 尝试添加新订阅
**Then** 操作被拒绝，显示"权限不足"提示
**And** 成员 B（编辑者角色）可以正常添加订阅

### 3. 审计日志追踪所有操作
**User Story**: 作为一名合规负责人，我需要查看所有用户的操作记录，以便在出现问题时追溯责任。
**Why this priority**: 审计日志是企业合规的基本要求。
**Independent Test**: 管理员在审计日志中查看过去 7 天内所有删除订阅的操作记录。

**Given** 系统已运行一周，多名成员执行了各种操作
**When** 管理员打开审计日志并筛选"删除订阅"操作类型
**Then** 显示所有删除操作的记录，包含操作人、时间、目标订阅名称
**And** 支持按时间范围和操作类型筛选

### 4. 集中管理仪表板
**User Story**: 作为一名 IT 运维人员，我想要在一个仪表板中查看所有成员的下载统计和存储使用情况，以便进行资源规划和问题排查。
**Why this priority**: 集中管理是降低企业运维成本的直接手段。
**Independent Test**: 管理员在仪表板中查看团队总下载量、各成员活跃度、存储使用趋势。

**Given** 团队有 10 名成员在使用系统
**When** 管理员打开集中管理仪表板
**Then** 显示本月总下载量、下载次数、存储使用量
**And** 展示各成员活跃度排名和下载量分布图
**And** 显示失败下载的汇总和错误原因分布

## Requirements *(mandatory)*

### 功能需求

#### 多用户支持
- **FR-001**: 系统必须支持多用户配置文件切换
- **FR-002**: 系统必须支持团队/组织创建和管理
- **FR-003**: 系统必须支持共享订阅源（团队级别）
- **FR-004**: 系统必须支持私有订阅源（个人级别）
- **FR-005**: 系统必须支持用户数据隔离（下载路径、设置）
- **FR-006**: 系统必须支持通过 LDAP/Active Directory 导入用户

#### 权限管理
- **FR-007**: 系统必须定义至少 3 种角色：管理员、编辑者、查看者
- **FR-008**: 管理员权限：管理团队、分配角色、管理订阅、查看审计日志
- **FR-009**: 编辑者权限：管理订阅（含共享）、触发下载、管理个人设置
- **FR-010**: 查看者权限：查看订阅和下载状态，不能修改任何数据
- **FR-011**: 系统必须支持自定义角色和权限组合
- **FR-012**: 权限变更必须立即生效，不需要重新登录

#### 审计日志
- **FR-013**: 系统必须记录所有关键操作（增删改查订阅、触发下载、修改设置）
- **FR-014**: 每条日志必须包含：操作人、时间戳、操作类型、操作对象、结果、IP 地址
- **FR-015**: 审计日志必须支持按操作人、时间范围、操作类型筛选
- **FR-016**: 审计日志必须支持导出为 CSV/JSON 格式
- **FR-017**: 审计日志必须防篡改（只追加，不修改，不删除）
- **FR-018**: 审计日志保留期可配置（默认 90 天，最大 365 天）

#### 集中管理
- **FR-019**: 系统必须提供企业管理仪表板（总下载量、活跃用户数、存储使用）
- **FR-020**: 系统必须支持批量管理操作（批量添加订阅到多用户）
- **FR-021**: 系统必须支持下载策略配置（配额、带宽限制、并发数限制）
- **FR-022**: 系统必须支持存储策略配置（保留期限、清理规则）
- **FR-023**: 系统必须支持使用量统计和报表生成

#### API 文档完整
- **FR-024**: 所有 API 接口必须有 OpenAPI 3.0 规范文档
- **FR-025**: API 文档必须包含请求/响应示例和错误码说明
- **FR-026**: API 文档必须包含认证说明和使用流程图
- **FR-027**: API 必须提供版本控制（通过 URL 路径或 Header）
- **FR-028**: API 文档必须支持在线浏览（Swagger UI）和离线 PDF 导出

### 关键实体

- **User**: 用户（id、用户名、邮箱、角色、所属团队、激活状态、最后登录）
- **Team**: 团队/组织（id、名称、创建者、成员列表、配额设置）
- **Role**: 角色（id、名称、权限列表 [Permission[]]）
- **Permission**: 权限（资源类型、操作类型：create/read/update/delete）
- **AuditLogEntry**: 审计日志条目（id、时间戳、操作人、操作类型、目标、结果、IP）
- **DownloadPolicy**: 下载策略（带宽限制、并发数、定时窗口、配额）
- **StoragePolicy**: 存储策略（保留天数、最大空间、清理触发条件）

## Success Criteria *(mandatory)*

### 可衡量的成果
- **SC-001**: 系统支持至少 50 个并发用户同时操作
- **SC-002**: 角色权限变更生效延迟不超过 5 秒
- **SC-003**: 审计日志写入不影响主要操作的响应时间（增加不超过 50ms）
- **SC-004**: 审计日志查询（90 天数据、10 万条记录）响应时间不超过 3 秒
- **SC-005**: 集中管理仪表板数据刷新间隔不超过 10 秒
- **SC-006**: 批量操作 100 个订阅的时间不超过 10 秒
- **SC-007**: API 文档覆盖率 100%（所有公开 API 端点）
- **SC-008**: 用户从登录到可操作的时间不超过 3 秒

## Assumptions

- 企业版功能基于本地网络部署，不强制要求云端服务器
- 用户认证在 P3 阶段使用本地账号系统，P4 阶段集成 LDAP/AD
- 审计日志存储在本地的 SQLite 数据库中（非 JSON 文件）
- 集中管理需要至少一台机器作为"管理节点"，其他为"工作节点"
- API 版本控制遵循语义化版本规范（v1、v2 路径前缀）
- 企业功能可能需要商业许可证，与社区版功能分离
- 权限模型基于 RBAC（基于角色的访问控制），不涉及 ABAC
