# Quality Checklist: 文件命名与组织

**Feature**: 009-file-naming-organization
**Phase**: P1 Enhancement
**Last Updated**: 2026-10-10
**范围**: 用户故事 1（文件名模板系统）+ 故事 4（文件夹自动组织，**并入故事 1**）+ 故事 5（文件冲突处理）。故事 2 / 3 已划出范围（见 spec 的「超出范围」）。
**依据**: 本清单的每一条都能追溯到 wayfinder 地图（[009 文件命名与组织](https://github.com/yysfire/yt-dlp-gui/issues/15)）上已关闭的决策票。**实现时逐项勾选**（参照 `specs/008-download-management-enhanced/checklists/requirements.md` 的用法）。

---

## 需求完整性检查

- [ ] 用户故事 1 / 4 / 5 的每个验收场景都有 Given/When/Then，且与 spec 的判定规则不冲突
- [ ] **两条硬校验已落实为「拒绝保存」**（不是警告）：模板必须含 `%(id)s`（FR-006）、必须含 `%(ext)s`（FR-007）
- [ ] **第三条硬校验**：模板含 `..` → 拒绝保存（FR-008）
- [ ] 白名单 11 个字段（FR-009）与禁入四项（FR-010）**已分别落成常量并有测试**
- [ ] 未知占位符 → **警告但允许保存**（FR-003）—— 注意这与 yt-dlp 的实际行为相反（yt-dlp 静默渲染成 `NA`、rc=0），所以警告必须由**我们**提供
- [ ] 三种冲突策略各有**行为测试**（存在性断言，非统计性）
- [ ] 「跳过」**仅首次下载**、**重下永不跳过**的约束已写进实现（FR-019）
- [ ] 「重下走统一冲突路径」已实现（FR-020）—— **现状是坏的**：`redownload_video` 对已存在文件零处理，实际什么都没下却标 `completed`
- [ ] 冲突信息在记录详情可见（FR-022）；「自动重命名」时显示新旧两个文件大小（FR-023），其余策略下该字段为空
- [ ] `skipped` 的**可重试**语义已实现（FR-021）—— 不进 seen 集合 / `dedup_rank` 排在 `failed` 之前
- [ ] 存量迁移 = **只对新下载生效**（FR-024），**未**实现任何自动改名/迁移逻辑

## 技术可行性检查

- [ ] **模板预览纯本地实现** —— **不调用 yt-dlp**（用示例数据做字符串替换）。理由：FR-002 要求 < 100ms 实时更新
- [ ] **不自研文件名字符净化**（FR-013）—— 透传 yt-dlp。**若有人实现删除式净化，此项打回**：实测会把碰撞从 1 组放大到 3 组
- [ ] **未引入 `--compat-options filename-sanitization`**（FR-011）—— 它会让 `id` 字段跳过全角替换改为删除
- [ ] **未实现 Unicode NFKC**（FR-012）—— `--restrict-filenames` 会把中文与重音全毁
- [ ] **未处理 Windows 保留设备名**（FR-014）—— `CON.mp4` 是合法真实文件；危险形状是「渲染后无扩展名」，已由 FR-007 覆盖
- [ ] 模板字面量的 `..` 校验已实现（FR-008）—— **yt-dlp 只 sanitize 字段值，不防模板自身穿越**（实测 `-o "trav/../../ESCAPED_%(title)s.%(ext)s"` 真写到目录外）
- [ ] 中间目录创建由 yt-dlp 负责（FR-005，下载前发生，无 flag 可关）—— **我们不自己 mkdir**
- [ ] 序号由 **Rust 侧**计算，插在扩展名之前（FR-016）—— **不用** yt-dlp 的 `%(autonumber)s`（`--autonumber` 已废弃 rc=2，且该字段已禁入）
- [ ] 「覆盖」策略已解决**旧文件回收**（FR-018）—— `--force-overwrites` 覆盖后 `old == file_path`，`download_queue.rs:823` 的守卫不成立 ⇒ 旧文件永不回收

## 用户体验检查

- [ ] 模板输入框有**占位符提示**（列出白名单 11 个字段）
- [ ] 模板预览**实时更新**（随输入，不需点击）
- [ ] 预览位置在**设置页内联**（`SettingsDialog.tsx` 是单页 Grid、无 Tabs）
- [ ] 「文件命名」区位置在**下载目录之后、yt-dlp 路径之前**（同一「文件落地」语义群）
- [ ] 冲突策略选择器为单选，三种策略并列
- [ ] 拒绝保存时**说明原因**（三条硬校验各有对应的提示文案，不能是笼统的「格式错误」）
- [ ] 未知占位符的警告文案点明「yt-dlp 会渲染成 NA」—— 避免用户困惑
- [ ] 所有设置项有合理默认值（默认模板须含 `%(id)s` 与 `%(ext)s`）

## 兼容性检查

- [ ] **路径独占性断言已落成测试**（SC-001）—— 条件式表述：「若渲染结果含该 video 的 id，则不同 `video_id` 必得不同路径」
- [ ] **反向护栏断言已落成测试** —— 断言「删除式净化不满足该性质」，防止日后有人把 FR-013 实现成删除法
- [ ] 跨 Windows/macOS/Linux 三平台路径独占性成立（SC-005）
- [ ] 路径过长时**只警告不截断**（截断会破坏路径独占性）
- [ ] 模板仅由 `%(id)s.%(ext)s` 组成时合法工作
- [ ] 频道名含 Windows 非法字符时由 yt-dlp 净化（全角等价物），我们不干预

## 安全性检查

- [ ] 模板**不会**导致路径遍历（`../`、`..\\`、混合分隔符全部拒绝）—— FR-008
- [ ] 用户输入的模板**不被**用于命令注入（模板作为 `-o` 的**单个 argv 元素**传入，不经 shell）
- [ ] 模板中的 `/` 由 yt-dlp 处理为对应平台的分隔符

## 测试覆盖检查

- [ ] 模板解析单元测试覆盖：白名单 11 字段、禁入 4 字段、未知字段、含 `..`、缺 `%(id)s`、缺 `%(ext)s`、纯 `%(id)s.%(ext)s`
- [ ] **核心不变式测试**（SC-001）：不同 `video_id` → 不同路径（条件式）
- [ ] 冲突策略单元测试覆盖：重命名序号（`(1)` 起、插扩展名前）、覆盖后的旧文件回收、跳过不调 yt-dlp
- [ ] `skipped` 状态的**可重试**行为测试（`dedup_rank` 排序 + seen 集合行为）
- [ ] **重下路径测试**（FR-020）：目标已存在时，**不得**静默标 `completed`
- [ ] `DetailPanel.tsx` 的**非穷尽** `status === "x"` 链已补 `skipped`（图标链 `:483-491`、文案链 `:522-564`、色条 `:68-70`、按钮矩阵 `:651-674`）—— **这些地方新增状态不会编译报错，只会静默不渲染**

- [ ] 与 `services/ytdlp.rs` 的命令构造兼容 —— `--encoding utf-8` **已在 `6ad6704` 加在统一收口**（`yt_dlp_command` / `yt_dlp_command_async`），**不要重复添加**
- [ ] 若改 argv 参数，同步改 `test_build_download_args_exact`（`ytdlp.rs:963-986`，**逐元素断言整个 argv**）

- [ ] 与前端 `SettingsDialog.tsx` 集成

- [ ] **引用 008 结论时用修订后的表述**（`路径独占性`，不是「一个文件」）—— 见 [修订 008「物理必然性」论证链](https://github.com/yysfire/yt-dlp-gui/issues/21)
