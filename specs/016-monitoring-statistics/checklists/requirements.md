# 需求质量检查清单: 监控与统计 (015)

## 需求完整性

- [x] 所有用户故事具有明确的 Given/When/Then 结构
- [x] 功能需求覆盖所有用户故事中描述的场景
- [x] 关键实体定义完整，包含必要的聚合数据结构
- [x] 成功标准可量化、可验证（包含性能基准）
- [x] 假设条件已明确记录
- [x] 图表类型和交互方式已在需求中指定

## 技术可行性

- [x] 统计聚合在 Rust 后端执行，计算复杂度为 O(n)，5000 条记录 < 2 秒可行
- [x] sysinfo crate 提供跨平台 CPU/内存监控，已在生态中广泛使用
- [x] Chart.js 或 ECharts 支持所需的所有图表类型（柱状图、折线图、饼图）
- [x] 磁盘使用分析基于文件系统元数据调用，可行且高效
- [x] 活跃度评分算法基于已有下载记录时间戳，无需外部数据

## 架构一致性

- [x] 统计计算作为独立服务（`statistics.rs`），聚合 download_records.json
- [x] 资源监控作为独立服务（`resource_monitor.rs`），通过 Tauri events 推送
- [x] 前端图表组件遵循 React + TypeScript 模式，与现有组件风格一致
- [x] 活跃度分析复用现有 subscription 和 download_record 数据
- [x] 统计面板集成到 AppShell 的 Tab 或新视图切换中

## 边界条件

- [x] 无下载记录时的统计面板显示（显示"暂无数据"占位符）
- [x] 只有失败记录时的成功/失败比例计算（避免除零错误）
- [x] sysinfo 在某些平台上无法获取特定指标时的降级策略
- [x] 磁盘分析中已删除文件的处理（仅分析下载记录指向的现存文件）
- [x] 大量数据点（> 5000）时图表按时间聚合并降采样
- [x] 网络文件系统上 file metadata 调用超时的处理

## 安全性

- [x] 系统资源监控仅读取数据，不执行任何写入操作
- [x] 统计聚合仅访问应用自身数据文件，不扫描用户文件系统
- [x] CSV 导出中的用户数据不包含敏感信息（Cookie、代理）
- [x] 磁盘分析中的文件路径在前端展示前脱敏处理（可选）

## 依赖与集成

- [x] sysinfo crate 已确认支持 Linux/macOS/Windows 三大平台
- [x] 前端图表库（Chart.js/ECharts）与 React + MUI 兼容
- [x] 统计服务与 StorageService 共享同一数据源
- [x] 资源监控与现有 StatusBar 组件集成
- [x] 图表导出功能通过 Canvas API 实现，无额外依赖

## 测试策略

- [x] 活跃度评分算法可单元测试（固定输入验证评分输出）
- [x] 磁盘使用分析聚合逻辑可单元测试
- [x] 资源监控的 sysinfo 封装可测试
- [x] CSV 导出格式可单元测试
