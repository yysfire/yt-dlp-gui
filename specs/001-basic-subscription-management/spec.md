# Feature Specification: 基本订阅管理

**Feature Branch**: `001-mvp-core-features`

**Created**: 2026-05-31

**Status**: Draft

**Input**: 来自 PRD v1.0，yt-dlp 桌面端订阅管理器

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 添加新订阅 (Priority: P1)

用户通过输入频道 URL 将 YouTube 或 Bilibili 频道添加到订阅列表中。系统解析频道信息（名称、描述、封面图等）并保存，用户可在订阅列表中看到新添加的订阅。

**Why this priority**: 添加订阅是整个应用的核心入口操作，没有此功能应用无法使用。

**Independent Test**: 在订阅管理页面输入一个有效的 YouTube/Bilibili 频道 URL，点击添加，验证频道信息是否正确显示在订阅列表中。

**Acceptance Scenarios**:

1. **Given** 用户处于订阅管理页面，**When** 用户粘贴一个有效的 YouTube 频道 URL 并点击"添加"，**Then** 系统解析频道信息，频道名称、封面图正确显示在订阅列表中，订阅状态为"启用"。
2. **Given** 用户处于订阅管理页面，**When** 用户输入一个已存在的频道 URL，**Then** 系统提示该频道已订阅，不重复添加。
3. **Given** 用户处于订阅管理页面，**When** 用户输入一个无效的 URL 或无法访问的频道，**Then** 系统显示明确的错误提示信息，不创建空的订阅条目。
4. **Given** 用户处于订阅管理页面，**When** 用户输入一个 Bilibili 频道 URL，**Then** 系统正确解析 Bilibili 频道信息并添加到订阅列表。

---

### User Story 2 - 查看订阅列表 (Priority: P1)

用户可以浏览所有已添加的订阅频道，列表中显示每个订阅的名称、封面缩略图、最后检查时间、是否有新视频等信息。

**Why this priority**: 订阅列表是用户管理所有订阅的核心视图，使用频率最高。

**Independent Test**: 添加多个订阅后，在订阅管理页面查看列表，验证所有订阅信息是否正确完整显示。

**Acceptance Scenarios**:

1. **Given** 用户已添加多个订阅，**When** 用户打开订阅管理页面，**Then** 以列表形式显示所有订阅，每个条目包含频道名称、封面图、状态标识。
2. **Given** 订阅列表中有超过 20 个订阅，**When** 用户滚动列表，**Then** 列表流畅滚动，所有订阅均可正常查看。
3. **Given** 用户尚未添加任何订阅，**When** 用户打开订阅管理页面，**Then** 显示友好的空状态提示，引导用户添加第一个订阅。

---

### User Story 3 - 删除订阅 (Priority: P1)

用户可以删除不再需要的订阅频道。删除后，该订阅从列表中移除，但已下载的视频文件不受影响。

**Why this priority**: 用户需要管理订阅生命周期，删除不需要的订阅是基本需求。

**Independent Test**: 在订阅列表中选择一个订阅并执行删除操作，验证该订阅从列表中消失。

**Acceptance Scenarios**:

1. **Given** 用户有一个已订阅的频道，**When** 用户点击删除并确认，**Then** 该订阅从列表中移除，本地存储同步更新。
2. **Given** 用户在删除确认对话框中，**When** 用户点击取消，**Then** 订阅保持不变，无任何变更。
3. **Given** 用户删除了一个订阅，**When** 用户再次查看下载记录，**Then** 之前该频道的下载记录仍然存在（不级联删除）。

---

### User Story 4 - 启用/禁用订阅 (Priority: P1)

用户可以对每个订阅独立控制其启用/禁用状态。禁用的订阅不会被定时检查，但保留在列表中，用户可以随时重新启用。

**Why this priority**: 用户需要对订阅检查行为进行粒度控制，而非一刀切地全部检查或不检查。

**Independent Test**: 将某个订阅切换为禁用状态，等待下次定时检查，验证该订阅没有被检查。重新启用后，验证下次检查会正常进行。

**Acceptance Scenarios**:

1. **Given** 某个订阅当前为"启用"状态，**When** 用户将其切换为"禁用"，**Then** 该订阅在列表中显示禁用标识，定时检查将跳过该订阅。
2. **Given** 某个订阅当前为"禁用"状态，**When** 用户将其切换为"启用"，**Then** 该订阅恢复正常状态，下次定时检查或手动检查将包含该订阅。
3. **Given** 多个订阅中有部分被禁用，**When** 用户执行"检查全部"操作，**Then** 仅检查已启用的订阅，禁用的订阅被跳过并显示相应标识。

---

### User Story 5 - 手动检查更新 (Priority: P2)

用户可以手动触发对单个订阅或所有已启用订阅的更新检查，立即获知是否有新视频。

**Why this priority**: 手动检查是定时检查的补充，满足用户即时检查的需求，提升使用体验。

**Independent Test**: 点击某个订阅的"检查更新"按钮，验证系统启动检查流程并返回最新视频列表。

**Acceptance Scenarios**:

1. **Given** 用户查看某个订阅，**When** 用户点击"检查更新"，**Then** 系统启动该频道的检查流程，界面显示检查进度。
2. **Given** 用户想看所有订阅的最新状态，**When** 用户点击"检查全部更新"，**Then** 系统依次检查所有已启用的订阅，界面显示总体进度。
3. **Given** 某订阅正在进行检查，**When** 用户再次点击"检查更新"，**Then** 系统提示该订阅正在检查中，不启动重复检查。

---

### User Story 6 - 订阅分组（基础）(Priority: P3)

用户可以将订阅归类到预设的分组中（如"学习""娱乐""音乐"），便于按类别筛选和管理。

**Why this priority**: 当订阅数量增多时，分组能显著提升管理效率。MVP 阶段提供基本分组功能，后续可增强。

**Independent Test**: 创建一个新分组并将若干订阅移动到该分组，验证列表可按分组筛选显示。

**Acceptance Scenarios**:

1. **Given** 用户有多个订阅，**When** 用户将某个订阅分配到"学习"分组，**Then** 该订阅在分组视图中显示在"学习"分类下。
2. **Given** 订阅列表中有多个分组的订阅，**When** 用户选择"全部"视图，**Then** 所有订阅按分组排列显示。
3. **Given** 用户选择一个分组进行筛选，**When** 用户点击"检查该分组更新"，**Then** 仅检查该分组内的已启用订阅。

---

### Edge Cases

- 用户输入的 URL 格式不标准（如包含多余空格、特殊字符）时，系统如何处理？
- 网络中断时添加订阅（需要调用 yt-dlp 解析频道），系统如何提示用户？
- yt-dlp 返回的频道信息不完整（缺少封面图、描述为空）时，列表如何展示？
- 用户同时订阅了同一频道的多个 URL 版本（短链、完整链、Bilibili vs YouTube）如何识别并处理？
- 删除订阅时该订阅正在检查/下载中，如何安全处理？
- 订阅数量超过 100 个时，列表性能是否可接受？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持通过 URL 添加 YouTube 和 Bilibili 频道订阅。
- **FR-002**: 系统必须在添加订阅时调用 yt-dlp 解析频道信息（名称、描述、封面图、频道 ID）。
- **FR-003**: 系统必须防止重复订阅同一个频道（以频道 ID 为唯一标识）。
- **FR-004**: 系统必须以列表形式展示所有订阅，包含频道名称、封面缩略图、启用/禁用状态。
- **FR-005**: 系统必须支持删除订阅，删除时需二次确认。
- **FR-006**: 系统必须支持对单个订阅启用/禁用自动检查。
- **FR-007**: 系统必须支持手动触发单个订阅的更新检查。
- **FR-008**: 系统必须支持手动触发全部已启用订阅的更新检查。
- **FR-009**: 系统必须支持将订阅分配到预定义分组。
- **FR-010**: 系统必须支持按分组筛选订阅列表。
- **FR-011**: 所有订阅数据必须持久化存储，应用重启后数据不丢失。
- **FR-012**: 删除订阅不应影响已下载的视频文件和相关下载记录。

### Key Entities

- **Subscription**: 订阅实体，包含频道名称、频道 URL、平台（YouTube/Bilibili）、频道 ID、封面图 URL、描述、所属分组、启用状态、创建时间、最后检查时间。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从输入 URL 到看到新订阅出现在列表中，耗时不超过 5 秒（在正常网络条件下）。
- **SC-002**: 订阅列表在包含 100 个订阅时，滚动帧率不低于 30fps。
- **SC-003**: 删除订阅的确认到完成操作耗时不超过 1 秒。
- **SC-004**: 禁用/启用订阅的状态切换响应时间不超过 500 毫秒。
- **SC-005**: 重复 URL 检测准确率达到 100%（通过频道 ID 匹配）。
- **SC-006**: 应用重启后，所有订阅数据完整保留，无数据丢失。

## Assumptions

- 用户设备已安装 yt-dlp 命令行工具，且版本兼容。
- 用户具有稳定的网络连接用于解析频道信息。
- 频道 URL 为 YouTube 或 Bilibili 的标准格式。
- 分组功能在 MVP 阶段使用预定义的固定分组，暂不支持用户自定义分组名称。
- 添加订阅时仅解析基本频道信息，不拉取视频列表。
