统一视频列表 · 详细设计

DetailPanel 重构：合并频道视频与下载记录为单一列表，支持后台自动加载全量数据

一、数据加载流程

1
即时渲染下载记录
records + queueTasks 已在内存中，无需等待即可展示。下载中的队列任务优先显示在最顶部。
2
加载第 1 页频道视频
调用 getChannelVideos(subscriptionId, 1, 10)，合并到统一列表。匹配到已有下载记录的视频，展示下载状态。
3
后台自动加载剩余页
异步递归加载第 2、3…N 页，静默追加到列表尾部。不使用"加载更多"按钮，用户无感知。切换订阅时取消进行中的加载。
4
完成态
全部频道视频加载完成 + 下载记录合并完成。旧的下载记录（不在频道视频列表中）保留在列表中。

二、数据结构

// TypeScript 新增类型
interface UnifiedVideoItem {
  // 频道视频信息（可能为 null，当仅来自下载记录时）
  channelInfo?: VideoInfo;

  // 下载记录（可能为 null，当仅来自频道视频且未下载时）
  downloadInfo?: DownloadRecord;

  // 队列任务（可能为 null）
  queueTask?: DownloadTask;

  // 派生字段
  readonly id: string;
  readonly title: string;
  readonly url: string;
  readonly status: VideoStatus;
}

type VideoStatus = "new" | "downloading" | "paused" | "waiting" | "completed" | "failed" | "cancelled";

三、合并规则

匹配键 规则 示例
video_id (优先) 频道视频 id === 下载记录 video_id 两者都达到同一平台 ID
video_url (回退) 频道视频 url === 下载记录 video_url 没有 video_id 的场景
仅下载记录 下载记录的 video_id/video_url 不在频道视频中 很久以前下载的旧视频
仅频道视频 频道视频 id/url 不在下载记录中 新发布的未下载视频

四、列表排序

  1. 下载中/等待中的任务 — 永远置顶（实时进度展示）
  2. 断点续传暂停的任务
  3. 已完成的下载记录 + 匹配到下载记录的频道视频 — 按下载时间倒序
  4. 未下载的频道视频 — 按上传日期倒序（频道最新优先）
  5. 仅来自下载记录的旧视频 — 按下载时间倒序（无频道视屏元数据时展示 less 信息）
  6. 失败的记录 — 最后

六、移除 DownloadRecordList

统一列表实现后，DownloadRecordList.tsx 组件可完全移除。DetailPanel 内部自行管理合并逻辑。

七、关键状态变化

触发事件 列表行为
切换订阅 清空列表，取消进行中的后台加载，步骤 1→2→3 重新执行
新下载开始 列表顶部若已有该视频，状态变为"下载中"并显示进度
下载完成 状态变为"已完成"，更新文件大小和时间
后台加载新页 静默追加到列表尾部，无闪烁
旧视频已下载 始终保留在列表中（无频道元数据也显示）
